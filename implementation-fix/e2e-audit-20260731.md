# Enterprise MES Browser E2E Audit

## Current structure

```text
e2e/
  machine/
    machine-flow.spec.ts
    ui/machine-validation.spec.ts
  resource-planning/
    resource-planning-flow.spec.ts
    concurrency/resource-planning-concurrency.spec.ts
    work-order/numbering.spec.ts
```

The Playwright configuration uses Chromium, serial workers, the real MES Console base URL, Keycloak login, failure screenshots/video/traces, and an HTML report under `artifacts/playwright/report`.

## Baseline and expansion

Before this audit there was one Machine browser test and four Resource Planning declarations, including two placeholders. The expanded suite contains seven declarations: two Machine tests and five Resource Planning tests. The Resource Planning smoke case no longer carries the misleading `@full` tag.

## Existing browser coverage

- Machine: creates a Machine Definition, creates identified Physical Machine Units, verifies duplicate serial rejection, creates a Workstation Machine Requirement, verifies the authoritative Resource Assignment, checks Ready and Blocked readiness, ends an assignment, verifies history, and verifies dependency-protected unit deletion.
- Machine validation: opens the real create form, submits empty required fields, and verifies the form remains visible with required controls.
- Resource Planning smoke: creates a Work Order from a released Production Version, runs Compute & Check, commits all Ready candidates, refreshes, and verifies persisted allocation state.
- Resource Planning validation: verifies zero quantity cannot be submitted.
- Resource Planning concurrency: creates two WOs, resolves the same Ready resource, uses two independent API contexts and a barrier, commits simultaneously, verifies one success and one controlled 409 conflict, and cleans both exact IDs.
- Resource Planning numbering: verifies sequential and concurrent business-code uniqueness with four disposable WOs and exact cleanup.
- Authorization: declaration exists but is skipped when dedicated Viewer credentials are unavailable. A runtime API probe with `X-Role-Code: VIEWER` returns HTTP 403 after the new backend guard.

## Findings and corrections

1. Concurrency was a real `test.skip`, not a test. It is now a barrier-synchronized test.
2. The execution allocation API previously accepted mutation requests without checking the role header. Allocation create, reallocate, and cancel now allow only planner/manager roles and return `RESOURCE_ALLOCATION_FORBIDDEN` with HTTP 403.
3. PostgreSQL serialization failures were exposed as internal SQL text. They now map to `RESOURCE_CAPACITY_CONFLICT` HTTP 409.
4. Cleanup previously accepted only one Work Order ID. It now accepts multiple exact UUIDs, reports remaining rows, and fails if any target header remains.
5. The Machine test failed when credentials were absent even though the expected behavior was an unavailable environment. It now explicitly skips with the missing prerequisite; it does not silently pass a mutation test.
6. The `full` Resource Planning command previously depended on a `@full` tag attached to one smoke case. It now executes the complete directory.

## Weak or missing coverage

- Machine edit, deactivation, deletion success, duplicate Machine Definition code/name, search/filter/sorting, unit edit/delete success, invalid effectivity, overlapping assignment, wrong Work Center, and all unit state transitions are not independently browser-tested.
- Resource Planning stale readiness mutations, cancellation/replan, execution start guards, capacity boundary variants, cross-site access, Operator/Admin role behavior, and logout/login persistence are not implemented as independent browser cases.
- Viewer authorization still needs a real Keycloak Viewer account to execute the browser login path. The backend denial path is verified independently without claiming the browser case passed.
- No separate page-object layer exists yet; selectors are stable `data-testid`/accessible-label selectors but helpers are still local to specs.

## Cleanup and fixture assessment

Mutating suites use unique namespaces and exact Work Order or namespace cleanup. Machine cleanup preserves shared fixtures and deletes child rows before parents. Resource Planning cleanup removes allocations, reservations, snapshots, operations, workflows, outbox references, and headers. Tests without required credentials are skipped before mutation.

## Package and CI assessment

Available commands now include Machine smoke/all, Resource Planning smoke/all/validation/concurrency/authorization/numbering, combined E2E, regression, and report commands. No CI workflow currently invokes these commands automatically; execution remains an explicit environment operation requiring runtime credentials and local database URLs for destructive cleanup.
