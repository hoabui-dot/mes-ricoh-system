# Correct MES Resource Hierarchy and Complete Resource Management UX

## Role

Act as a senior MES domain architect, database engineer, backend engineer, frontend engineer, and enterprise UX designer.

The current resource-planning backend has progressed through Phase 3, but the MES resource master-data UX and hierarchy remain incomplete and inconsistent.

Fix the resource domain and MES Console experience before claiming the resource-planning workflow is complete.

Do not apply route-label-only changes. Audit and correct the database model, API contracts, forms, relationships, migrations, and UI together.

# 1. Required Resource Hierarchy

Use this canonical hierarchy:

```text
Factory / Site
└── Shopfloor
    └── Work Center
        └── Workstation
            └── Machine

Meanings:

Site / Factory
= The physical plant and highest resource scope.

Shopfloor
= A production workshop or major manufacturing floor inside a Factory.

Work Center
= A logical capacity group referenced by Routing.

Workstation
= A logical execution station where operators receive and execute jobs.

Machine
= A physical production machine.

Do not model Workstation as a Factory.

Do not make Workstation independently select both Factory and Shopfloor when these values can be derived through its Work Center.

Do not repurpose the current Production Area concept as Factory without auditing existing Site relationships. Site already represents the factory boundary.

3. Introduce or Clarify Shopfloor

The target hierarchy requires an explicit Shopfloor level.

Preferred model:

interface Shopfloor {
  shopfloorId: string;
  shopfloorCode: string;
  shopfloorName: LocalizedText;
  description?: LocalizedText;

  siteId: string;

  status: "Active" | "Inactive";

  createdAt: string;
  updatedAt: string;
}

Relationship:

One Site has one or more Shopfloors.
One Shopfloor belongs to exactly one Site.
One Shopfloor has one or more Work Centers.

If the existing Production Area model can safely represent Shopfloor, restrict or migrate its active business meaning explicitly.

Do not retain misleading UI terminology such as Production Area when the user-facing entity is a Shopfloor.

Recommended Vietnamese label:

Xưởng

Recommended English label:

Shopfloor

20. Migration Strategy

Create forward-only migrations.

Do not rewrite applied Phase 1–3 migrations.

Required migration workflow:

Audit existing Site, Production Area, Work Center, Workstation, Machine, and Assignment rows.
Determine which Production Area records can be classified as Shopfloors.
Add Shopfloor entity/table or an explicit constrained Area subtype.
Add Work Center → Shopfloor relationship.
Add Workstation → Work Center relationship if missing.
Remove or deprecate redundant direct Site/Area inputs only after backfill.
Preserve old IDs and references.
Backfill derived Factory relationships.
Detect orphan or ambiguous records.
Generate a data-quality report for records that cannot be migrated safely.
Add constraints only after validation.
Preserve Work Order allocation snapshots and existing resource references.

Do not fabricate Factory/Shopfloor relationships when no evidence exists.

21. Required Constraints

Enforce server-side and database-level rules where practical:

Shopfloor belongs to one Factory.
Work Center belongs to one Shopfloor.
Workstation belongs to one Work Center.
Machine placement is governed by Resource Assignment.
Workstation create requires at least one Machine assignment according to the requested policy.
All resources in one Assignment belong to the same Factory hierarchy.
One Machine cannot hold overlapping Primary Workstation assignments.
Inactive resources cannot receive new assignments.
OutOfService Machines cannot be assigned for active scheduling.
Generated codes are unique.
Historical entities cannot be destructively deleted when referenced.
